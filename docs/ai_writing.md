# 本机 AI 文字助手：正文、朗读与接收屏分享

2026-11-03。已完成升级目录内的功能接入、离线回归及 PYNQ 独立 CPU 文件检查；本轮没有启动眼控界面、播放声音、加载位流或发送无线消息。用户暂不能配合，真人与混合负载验收集中留到后续。板端正式运行目录仍保持此前版本。

## 功能与操作路线

显式启用 `--ai-writing` 后，入口为：**更多 → 快捷交流 → 文字输入 → 编辑展示 → 文字助手**。未启用该参数时，原来的展示收藏入口与操作不变。

| 任务 | 操作 | 结果 |
| --- | --- | --- |
| 生成短句候选 | 先输入或载入正文 → 文字助手 → 生成候选 → 阅读完整候选 → 继续确认 → 替换正文 | 候选替换正文，可在修改页撤销；不自动收藏、朗读或发送 |
| 朗读正文 | 文字助手 → 朗读正文 → 等待声音准备 → 核对完整正文 → 确认朗读 | 播放本次确认的正文；可以停止或求助，完成后不重播 |
| 展示与收藏 | 文字助手 → 展示收藏 | 继续使用原有大字展示、收藏操作 |
| 无线发送 | 返回编辑展示 → 接收屏分享 → 文字与状态 → 预览正文 → 继续确认 → 确认发送 | 沿用现有正文分享协议，三端接纳后按原交流页显示 |

生成仅面向当前正文的短句补全、整理，不提供聊天机器人入口。未完成的拼音必须先选字或取消，避免丢失半成品。原正文、简拼/全拼、词句候选、撤销、收藏和所有休闲功能保留。

无线分享独立要求 `--receiver-sharing --eye-events live`。单独开启 AI 不会开启无线。正文分享保持原 64 字、字符编码、完整预览、发送确认、断线不补发及照护优先规则，不新增消息类别或接收端固件。普通正文不成为喝水/休息/帮助告警，也不获得护理确认含义。接纳回执不代表人工已读。

## 运行实现

- 复用上一阶段 MiniMind2-Small Q8 与 ARMv7 C 推理器，模型在 PYNQ CPU 本地运行，没有电脑推理服务或云端接口。生成结果长度 1–64 字，必须在现有可显示字符集合内；不支持的字符、过长或达到生成上限的结果整体拒绝，不静默截断。
- 推理和语音合成使用独立进程，一次只允许一个任务。主眼控循环只轮询结果，不等待推理完成；低优先级、CPU 亲和性、192 MiB 地址空间、CPU 时间、60 秒任务超时和 4 MiB 单文件限制约束资源。实际眼控并发响应仍需板测。
- 中文正文采用 eSpeak NG 普通话离线合成，转换为单声道 16 kHz PCM16；最长 60 秒，峰值限制为 8191。只在用户再次确认后，由原双缓冲音频通道播放。它是轻量规则合成语音，不能等同于此前录制的成熟男声；清晰度、音量和自然度尚待实际听感检查。
- 专用 `audio_file_only.c` 适配层使合成库不创建 ALSA/PulseAudio 音频后端。合成进程只输出 WAV，声音输出仍由原主进程管理。初版系统音频后端的共享内存初始化曾触发文件限制，失败记录已归档；修复后保留原限制，短句与 64 字均通过。
- 候选出现时清除旧停留进度，并要求视线释放，防止等待期间的注视直接成为新页确认。任务取消、正文变化、退出、辅助重新定位都会使待处理声音或结果失效。朗读需来自有效且新鲜的实时选择；帮助先停朗读，再进入原帮助语音和无线链路，不自动续读。
- 临时正文、候选和 WAV 保存在本次私有运行目录，正常取消/结束时回收。异常进程退出可能遗留本次私有临时目录，不会自动载入或发送其中内容。日志只增加计数，不追加私有正文。

| 项目 | 结果与边界 |
| --- | --- |
| 软件回归 | 559 项通过，含候选双确认、撤销、取消/晚到结果、正文变化、非法文字、语音确认、新鲜度、帮助抢占、重新定位及已有功能 |
| 界面 | 7 个状态渲染审阅；64 字完整预览渲染检查；四个大目标位置保持原布局 |

| PYNQ 静默语音 | 12 字合成与归一化 4.583 秒，62048 个样本；64 字重复测试 10.142 秒，270565 个样本。没有实际播放，不作听感结论 |
| 后端隔离 | 最终加载依赖不含 ALSA/PulseAudio；静态合成系统调用检查未见音频设备、MMIO 设备或 socket/connect 调用 |
| 输出离线贯通 | 实际生成文字与实际 WAV，经正文确认、模拟完整播放、分享双确认进入真实 C 桥接/三端状态机；62048 样本完整，三端文本一致，无提前提交 |
| 原分享回归 | 7 组 Python→C 离线整链通过，覆盖 64 字、TEST 静默、确认后视线失效、缺回执、帮助抢占及照护页保护 |
| 保护项 | 181 个上一阶段本地保护文件不变，另 5 个运行源码按本轮范围修改；板端 154 个原文件及个人数据核对一致，检查结束硬件空闲、SSH 关闭 |

极小语言模型仍可能偏题或生成不完整表达；内容核对与采用权由用户保留。本轮不声称识别准确率提升，也没有启用候选神经网络位流或更换个人眼控模型。

## 文件与后续部署

候选包：`build/ai_integration_20261103/eye_ai_integration_candidate.zip`。它是增量候选包，不是整工程覆盖包；含新增运行文件、5 个需合并的现有运行文件、AI/语音资源、回滚原件及哈希清单。没有个人模型、默认配置、媒体库、收藏/书签/音量、位流或四板固件。资源约 37 MiB，精确字节数见阶段 `result.json`。

后续只在用户能配合时安排一次集中检查：硬件独占与哈希核对 → 合并候选文件并补充升级清单 → 原功能关闭 AI 的预检 → 显式启用 AI → 短句候选/取消/采用/撤销 → 朗读、帮助打断 → 确认无线正文与接收屏显示 → 音乐/视频混合及 BTN2/BTN3。原固定机位、门限和媒体不改，不重编四块通信板。待听感和混合负载通过后再考虑成为常用启动选项。

本轮仅执行 `launch.prepare_launch` 的离线计划生成，保存于阶段 `launch_plans.json`，没有调用启动服务。示例沿用 `build/fixed_camera_calibration_20261103/ui_profile.json` 的 300 秒显式配置，并附加已验证功能参数与 `--ai-writing`。实际部署前仍需核对当前机位和独占状态。

主要代码：`ai_bundle.py`、`ai_jobs.py`、`ai_worker.py`、`ai_writing.py`；接入点为 `daily_tools.py`、`appearance_trial.py`、`board.py`、`launch.py` 和图标别名。复查工具：`tools/verify_software.py`、`tools/verify_ai_integration.py`、`tools/preview_ai_writing.py`。`tools/check_ai_worker_cpu.py` 是需要显式远程权限的静默检查工具，不能作为眼控启动器。

## 依赖来源

模型和推理器延续 [上一阶段固定版本与许可](edge_ai_v2.md)。语音二进制取自 [Ubuntu Jammy ARMHF eSpeak NG](https://packages.ubuntu.com/jammy/armhf/espeak-ng)，版本 1.50+dfsg-10；文件逐项 SHA256 随 `assets/ai/manifest.json` 保存。普通话数据与许可证随包。
