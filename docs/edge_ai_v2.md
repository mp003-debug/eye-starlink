## 眼控神经网络的运行优化

沿用上一阶段已训练的 1152→64→32→5 MLP，不重新训练或改变权重。新增 C INT8 内核、ARMv7 NEON 向量点积、输出连续存储的权重布局、固定大小临时缓冲，以及显式 Python 调用接口。去除逐帧权重类型转换；模型只加载一次。原有几何绑定、旧分类器先拒绝、神经网络一致性与置信门限继续保留。

| PYNQ CPU 检查项 | 实测结果 |
|---|---:|
| 原 NumPy INT8 网络推理中位耗时 | 6.284 ms |
| 新 C/NEON 网络推理中位耗时 | 0.537 ms |
| 新内核 P95 | 0.590 ms |
| 中位耗时加速比 | 11.70 倍 |
| 紧凑模型文件 | 76,800 字节（75 KiB） |
| 原 NPZ 文件 | 355,349 字节 |
| 文件大小减少 | 78.4% |

同一组 50 条保存特征在板端新内核运行 1,000 次，旧内核运行 200 次；全部输出最大差为 0。最终 Python 封装又核对了 50 条。另有 67 条随机及边界特征的本地检查，输出最大差也为 0。此处测量的是网络推理阶段，不包含相机、眼部对齐、显示、音频和无线处理，不代表整个系统加速 11.70 倍。

接口：`src/eye_tracker/neural_native.py`。使用 `NativeNeuralModel` 显式加载，支持上下文管理和关闭；`attach_native` 只允许在新中央参考之前绑定同机位模型。现有启动器没有自动启用该候选。本轮没有加载上一阶段的 FPGA 神经网络位流；64 DSP 的候选仍属于此前离线实现结果。

## 极小中文语言模型

采用公开预训练的 **jingyaogong/MiniMind2-Small**，固定版本 `8c0c0de640cd532fee03d329b95a58c56591b5bc`。25,829,888 参数，8 层、512 维、8 查询头/2 KV 头、6,400 词元。原模型和预训练工作归原作者；本项目完成 Q8 转换、ARM NEON 内核适配、按需词嵌入解码、纯 Python 分词器与板端受限运行封装。

推理内核基于 MIT 许可的 `karpathy/llama2.c`，固定版本 `350e04fe35433e6d2941dce5a1f53308f87058eb`；模型 Apache-2.0 许可与来源清单随包保留。具体改动包括匹配原模型的 RoPE 排列、1,000,000 频率基数、GQA、共享输出嵌入和 RMSNorm；去除整张词嵌入的浮点展开，节省约 12.5 MiB 分配。

| 配置或板端结果 | 数值 |
|---|---:|
| Q8 权重文件 | 27,470,080 字节（26.20 MiB） |
| 固定上下文上限 | 256 词元 |
| 输入/新生成上限 | 192 / 64 词元 |
| 首组三个提示实际生成 | 5 / 32 / 32 词元 |
| 首组三个提示预填充等待 | 3.155 / 2.362 / 3.947 秒 |
| 两次 32 词元生成阶段速度 | 约 6.2 词元/秒 |
| 六次板端运行峰值 RSS | 27.75–28.00 MiB |
| 六次提示预填充范围 | 2.36–6.05 秒 |

速度按两次达到 32 词元上限的运行计算：首词元来自预填充，后续 31 次前向耗时约 4.99–5.00 秒。RSS 为 C 推理进程自身的 Linux `getrusage` 结果，含映射权重驻留页，不是整个 PYNQ 系统或 Python 父进程的内存。测试时眼控及多媒体停止，没有测量并行负载。

分词器经过 8 条固定样例及 500 条随机混合 Unicode 字符串与官方实现比对。三个板端完整提示与桌面同一 C 实现的输出词元一致，最终提示 logits 最大差不超过 2.39e-6。独立 NumPy/HF 排列参考则有约 0.25–0.33 的最大 logits 差，原严格数值标准未通过：调试发现微小浮点差跨越动态量化边界并逐层放大；三个提示的最高分词元一致、余弦相似度超过 0.9998。该结果作为近似转换核对保留，不宣称与原 FP16 模型逐位一致或语言质量无损。

## 实际输出与使用定位

独立命令行补测的三个输出均在板端真实生成，未人工改写：

| 提示 | 输出 |
|---|---|
| 续写一句简短的第一人称请求，只输出续写后的句子：我想喝水，请 | 我想喝水，请。 |
| 把这句话改成礼貌请求，只输出一句话：请帮我换个姿势。 | 当然，我很乐意帮助您转换成礼貌请求。请告诉我您需要什么样的 |
| 续写一句话，不要解释：今天下午，我想 | 今天下午，我计划去公园散步。 |

第二条达到 24 词元上限，输出未结束。第一条也未形成完整请求。因此当前结论为“PYNQ 本机运行可行，短句质量有限”，尚不适合自动代替用户表达。已有一条正常短句不代表普遍指令遵循能力。生成结果必须经过用户选择和确认；当前只保存在独立试验输出，没有接入眼控正文、语音或无线发送。

## 独立运行入口

板端研究目录：`/home/xilinx/Eye_Tracker_Upgrade_Version/build/edge_ai_v2_20261103`。

```sh
sudo python3 /home/xilinx/Eye_Tracker_Upgrade_Version/build/edge_ai_v2_20261103/tiny_language_cli.py \
  --bundle /home/xilinx/Eye_Tracker_Upgrade_Version/build/edge_ai_v2_20261103 \
  --prompt '续写一句话，不要解释：今天下午，我想' --max-new 24
```

入口校验文件 SHA、ARMv7 平台和独立目录，并取得既有独占锁、检查设备空闲。子进程限制 160 MiB 虚拟内存、110 秒 CPU 软限制/115 秒硬限制、120 秒等待；使用低优先级并绑定 CPU1（可用时）。固定短上下文、拒绝用户嵌入控制标记，stdout 只返回文字及指标。该入口目前用于独立研究，运行眼控时会因独占锁拒绝启动。
