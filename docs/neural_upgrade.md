# 轻量神经网络与 FPGA 定点加速（本地候选）

后续 CPU 优化及 PYNQ 本机语言模型试验见 [第二阶段记录](edge_ai_v2.md)。下文为此前仅本地开发阶段的记录。


本阶段仅在升级工作目录开发、训练、回放、仿真和构建。PYNQ 与四块通信板没有连接、下载或联调；默认启动入口继续使用原模型与原位流。比赛技术文档在后续阶段更新。

## 已实现的技术路径

采用与当前固定机位标定绑定的轻量 MLP：1152 维归一化眼部特征 → 64 单元 ReLU → 32 单元 ReLU → 5 类方向。共 76,037 个可训练参数，每次推理包含 75,936 次有效乘加。输出为中央、喝水、休息、帮助和更多对应的五个视线区域。

网络由现有 50 张拟合帧真实训练。训练种子、400 个 epoch、学习率、增广方式和最终 epoch 取模策略在读取评估帧前固定。八份噪声增广只来自拟合特征，不增加独立样本数。25 张留出帧和另一次采集的 25 张方向检查帧未用于训练或选择模型。

权重和层输入使用对称 INT8，点积累加为 INT32。逐层量化比例由拟合数据确定；偏置、反量化和 ReLU 在 PS 端进行。因此这是“INT8 乘加加速的混合推理”，不是整网全整数电路，也不是 CNN、DPU 或大语言模型。

已有眼角对齐、图像范围、陌生外观、方向歧义、时效性、停留选择与释放保护保持原样。`attach_neural` 提供独立显式接入：旧分类门限通过后，还需神经网络同意且置信度不少于 0.8、概率差不少于 0.5。分歧、超时或硬件故障均拒绝当前帧，不借用上一帧结果。原有音乐、视频、听书、游戏、文字、相册、表情和无线业务处理不修改。

## FPGA 实现

新增 `neural_mac_axi.v`，使用 32 路有符号 INT8 乘加。权重分为 32 个 BRAM 银行，最多 4096 行，每行并行读取 32 个权重；当前网络使用 2400 行（76,800 字节，包含末层填充）。输入缓存最大 2048 字节，返回每组最多 32 个 INT32 点积。

第一层输出 64 个神经元，分两组计算；第二层一组；第三层五个输出占一组。各组计算周期为输入长度加 2，整网四组共 2408 个核心时钟周期。在设计的 50 MHz 时钟下对应 48.16 微秒纯核心计算预算；不包括 AXI 上传、Python 调度、特征提取、层间处理等，不能作为板端推理时延或系统加速比。

权重只需一次顺序装载，重复推理复用片上存储。硬件验证连续写入长度，未完整装载不能启动；运行中禁止改权重、输入和配置。支持独立 AW/W、读写响应背压、非法访问报错、复位清除有效性、显式中止及看门狗。软件驱动核验 IP 标识、模型绑定与装载状态，并有界等待；没有隐式加载位流、连接板卡或启用功能的行为。

地址 `0x43C40000`，窗口 256 KiB。原相机、VDMA、显示、音频、GPIO 和无线 UART 的地址及接线保留；增加第六个 AXI 控制从设备。独立构建输出位于 `build/neural_upgrade_20261103/fpga`，不使用或覆盖原 `fpga/project`、`build/fpga`。

| 偏移 | 用途 |
|---|---|
| 0x00 / 0x04 | 标识 NN32 / 版本 1.0 |
| 0x08 | 命令：1 启动、2 中止、4 清状态并失效装载 |
| 0x0C | bit0 busy、bit1 done、bit2 fault |
| 0x10 / 0x14 / 0x18 | 输入长度 / 权重起始行 / 输出数量 |
| 0x1C / 0x20 / 0x24 | 完整权重行数 / 输入字数 / 核心周期 |
| 0x1000–0x17FF | 输入缓存，每字四个小端 INT8 |
| 0x2000–0x207F | 最多 32 个 INT32 输出 |
| 0x10000–0x2FFFF | 权重，按行优先、每行 32 个 INT8 |

## 离线验证与复现

1. `tools/train_neural_candidate.py`：固定训练方案，只接受新的模型输出目录，防止覆盖已冻结候选。
2. `tools/evaluate_neural_candidate.py`：校验原始帧 SHA-256、训练/检查隔离、浮点与 INT8 方向及组合拒绝。
3. `tools/replay_neural_pipeline.py`：保存图像与模拟时钟驱动现有稳定性/停留流程，验证持续注视只触发一次、移开释放与故障拒绝；重复图像不算真人测试。
4. `tools/verify_neural_rtl.py`：XSim 实际计算 50 组网络的 5050 个点积，并检查边界、背压、初始化、中止、复位、超时与核心周期。
5. `tools/verify_software.py`：运行既有功能和新增模型/驱动回归。
6. `tools/build_neural_overlay.py`：创建独立全系统工程，实际综合、布局布线、时序/DRC/CDC 检查并导出 bit/HWH。

Python 使用现有 bundled runtime。图像回放使用 `tools/deps/opencv`。训练无需 PyTorch、联网服务或新增系统依赖。XSim/Vivado 在本机受限进程中出现 DLL 加载问题时，需使用获准的本地构建进程；不修改 AMD 安装目录。

## 使用边界与下一阶段

候选包含真实模型、CPU 推理、MMIO 驱动、RTL、仿真、构建输出及散列清单。默认启动器不调用新模块；现有校准证据也不被当作新神经网络的板端验收。后续上板授权后，先独占硬件核对寄存器和定点结果，再完成新鲜方向/无效输入验证，最后显式接入眼控和混合功能负载。BTN2 重定位必须重新建立当前参考并重新附加同一冻结网络。

现有离线样本来自同一参与者、同一固定机位，不能据此宣称跨人群准确率、患者有效性或速度提升。该阶段增加的 DSP/BRAM 必须由最终实现报告确认，资源增加服务于实际推理计算和权重存储。

AMD 设计参考：[Vivado Synthesis UG901](https://docs.amd.com/r/en-US/ug901-vivado-synthesis)；[7 Series DSP48E1 UG479](https://docs.amd.com/api/khub/documents/gu4oRPFEh_Pm2uaAlfY6Kg/content)。
