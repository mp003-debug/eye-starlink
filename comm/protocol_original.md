# 当前通信契约（升级接入不改线协议）

PYNQ → 3.3V UART1 → A/01 → SLE三条连接 → 02/03/04。
A自身EYE_NODE_ID=0；02/03/04分别为1/2/3，配置符号B/C/D是历史内部命名。
三端必须全部就绪；EYE_REQUIRED_MASK=0x7。不能把某一个接收端的本地READY当作全组READY。
A按三个接收端分别确认后生成汇总UART ACK，界面本地选中不等于无线成功。

| code | 动作key | 三端处理 |
| --- | --- | --- |
| 1 | water | 喝水需求 |
| 2 | rest | 休息需求 |
| 3 | help | 求助，现有应用保持优先级 |
| 4 | more | 导航，仅接纳，不改变通知页面 |
| 5 | back | 导航，仅接纳，不改变通知页面 |

新音乐/视频/表情/小游戏/听书/拼音输入/收藏/快捷句动作不自动分配新code，也不冒用1–3。
自定义文字和新增快捷句当前没有无线载荷协议。若要远端显示这些内容，需另定版本和接收端实现。

## PYNQ UART帧（16字节）

| 偏移 | 内容 |
| --- | --- |
| 0..1 | A5 5A |
| 2 | 版本01 |
| 3 | HELLO=0x01 / PING=0x02 / EVENT=0x10 / ACK=0x80 |
| 4..7 | 非零session，uint32小端 |
| 8..11 | sequence，uint32小端；HELLO=0，后续递增、不回绕 |
| 12 | EVENT code，HELLO/PING为0，ACK回显 |
| 13 | 请求flags：0=LIVE、1=TEST；ACK时为status |
| 14..15 | 前14字节CRC-16/CCITT-FALSE，小端 |

CRC poly0x1021、init0xFFFF、refin/refout=false、xorout0，123456789→0x29B1。
参考向量在pynq/protocol_vectors.json；Python/C编解码源码随包。
UART FIFO16字节，单请求在途。调试日志不能写入业务UART。

ACK status：0接纳、1已接纳的重复（不重复执行）、2会话不符、3旧序号/同序号不同包、
4非法事件、5模式不符、6应用未就绪或队列满。
TEST=1仅打印EYE TEST，不调用动作接口；LIVE flags=0才向显示任务有界队列交付。

## 时序与故障语义

- 单调毫秒时钟，真实完成停留的Action仅提交一次，不能直接发送原始注视候选。
- 首发新鲜度150ms；空闲500ms心跳；同一帧180ms后可重试，总限600ms、最多3次发送。
- EventLink.service间隔超过250ms会中止旧会话；收端会话空闲超时2000ms。
  升级视频解码、音频供给和页面渲染不能阻塞这条服务路径，不能只靠放宽时限掩盖卡顿。
- 新事件不能在离线状态积压；只有一项新鲜事件可暂等在途心跳。
- 暂停/取消/输入失效/重新校准/退出/传输错误取消未发请求和重试；已发出的通知不能撤回。
- 超时且曾发送记delivery_unknown；不能声称对端必定没收到，也不能重新编号自动再发同一动作。
- 重传维持session+seq，接收端去重；跨断电不承诺持久化恰好一次。
- 一个接收端掉线时全组不能报告成功；已接受的部分动作不会被回滚。

“通信接纳ACK”“屏幕显示完成”“SW1人工确认”“SW2处理完成”是不同状态。
目前仅第一种沿无线返回；后两种是03/04本地状态，不存在护理人员确认的上行协议。
