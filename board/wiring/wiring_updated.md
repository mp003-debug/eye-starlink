# 最新硬件接线：03/04墨水屏、按键和LED

版本：用户在本聊天2026-11-01提供的两张更新图。两块墨水屏接收端采用同一接法。
物理脚号按用户新图抄录，GPIO与实际构建的wearable_epd.c核对；这不等于逐根测量实物。

## 每块墨水屏接收端

| 墨水屏转接板丝印 | 小熊派物理脚号 | 信号 | 接法 |
| --- | --- | --- | --- |
| 3V3 | 1 | 3.3V输出 | 直连 |
| GND | 2 | GND | 直连 |
| BUSY | 27 | GPIO5 | 直连 |
| RST | 36 | GPIO12 | 直连 |
| D/C | 34 | GPIO10 | 直连 |
| CS | 22 | GPIO0 | 直连，同时分支接R1 |
| SCK | 31 | GPIO7 | 直连 |
| SDA | 32 | GPIO8 | 直连；这里是SPI数据输入MOSI，不是I²C |

R1为10kΩ上拉：一端接3V3，另一端接CS/GPIO0公共网络。GPIO0到CS保持直接相连。

```text
3V3 ── R1 10kΩ ──┐
                  ├── 墨水屏CS
GPIO0 ────────────┘
```

| 新增元件 | 具体接线 | 现有软件定义 |
| --- | --- | --- |
| SW1 确认收到 | 物理脚7/GPIO13 → R2 1kΩ → 常开按键 → GND | 内部上拉，低电平按下 |
| SW2 处理完成 | 物理脚8/GPIO14 → R3 1kΩ → 常开按键 → GND | 内部上拉，低电平按下 |
| LED1 红灯 | 物理脚24/GPIO2 → R4 1kΩ → LED阳极；阴极→GND | 高电平点亮，初始化为低 |

R2/R3是串联电阻，不是上拉。按键去抖由连续三次低电平采样和释放锁存实现；
主循环等待上限25ms，不把名义采样周期当作严格按键延迟保证。
GPIO5/BUSY使用PIN_MODE_4，其余上述GPIO使用PIN_MODE_0，保留实际源码设置。

## 按键、显示与红灯的实际现有语义

- 有待处理需求时SW1置本机acknowledged状态并切换相应确认页面；无需求时不产生新事件。
- SW2清除本机需求并回待机。两个按键都不发送星闪业务回执到A或PYNQ。
- LED由g_request驱动：普通需求名义慢闪、帮助名义快闪、无需求熄灭。
  当前SW1只改变确认状态，**不会直接熄灭LED**；SW2清除需求后才熄灭。不得把“确认后灭灯”写成已实现。
- HELP保持优先级。之后的water/rest可以获通信接纳，但不覆盖待处理HELP页面；先本机完成/清除。
- 控制任务与墨水屏刷新任务分开；通信ACK是入队接纳，不是屏幕刷新结束，也不是SW1人工确认。

## PYNQ到A/01（保持）

| PYNQ Arduino口 | A/01小熊派 |
| --- | --- |
| AR1/D1 TX（FPGA U12） | RXD GPIO16/UART1_RX，物理脚10 |
| AR0/D0 RX（FPGA T14） | TXD GPIO15/UART1_TX，物理脚9 |
| GND | GND |

115200/8N1、3.3V逻辑、三线、分别供电；不接板间电源脚。PYNQ用配套12V/J9 REG。
接线调整在断电时进行；A独立USB或电脑USB供电。USB UART0用于日志，与业务UART1分开。

## 02串口屏（保持用户现有接法）
